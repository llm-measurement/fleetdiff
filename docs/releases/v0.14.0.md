Draft release preparation. Not tagged or published; merge, tagging and release
each require maintainer approval.

Compare two periods of LiteLLM spend logs or Langfuse exports to see which
recorded agents drove token and spend changes. Choose an explicit agent ID or
request-tag source; the report does not guess agent identities.

## Agent Attribution

- Use `--group-by agent --agent-source agent_id` for LiteLLM's recorded agent IDs.
- Use `--agent-source request-tag --agent-tag-prefix 'agent:'` for LiteLLM or
  Langfuse tags. Identical repeated tags resolve to one agent; distinct matching
  labels remain ambiguous, and unknown/ambiguous rows retain their accounting.
- Rank signed token changes, or add `--rank-by recorded-spend-change` for exact
  recorded-USD changes. USD-unavailable agents stay visible even with `--top`.
- See the answer sentence, before/after tokens and USD, period shares and
  unattributed changes. Cost-coverage columns appear only for incomplete
  displayed costs. Recorded USD is not a provider invoice.
- Raw selected labels require both disclosure flags and are escaped in text.
  Identical Langfuse labels remain project-scoped and use project aliases;
  raw project names are not displayed.
- Keep invalid LiteLLM tag-element rows as unknown identity with separate
  coverage. Langfuse retains string-only validation. Exact agent counting is
  bounded to 1,024 identities; no silent truncation occurs.

The synthetic fixture records 300 -> 620 tokens and USD 3 -> 6.20. Alpha adds
200 of the 320-token net increase (62.5%). See the
[agent guide](../AGENT_ATTRIBUTION.md) for commands and limits.

## Breaking Routing Label Disclosure

Routing `--show-labels` now also requires `--acknowledge-sensitive-labels`.
Replace an existing routing command such as:

```sh
fleetdiff investigate --litellm-spend spend.csv --routing-audit --show-labels
```

with:

```sh
fleetdiff investigate --litellm-spend spend.csv --routing-audit \
  --show-labels --acknowledge-sensitive-labels
```

The same two flags disclose selected agent labels. User, session, end-user and
key rankings remain aliased. Default exports and reports remain byte-identical
to v0.13.1; the agent JSON section retains its independently versioned contract.
No new runtime dependency is introduced.
