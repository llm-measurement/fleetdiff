# v0.11.0 Release Notes

**See which models served each LiteLLM route, and re-price the traffic selected
by route or agent.** The audit shows recorded requests, tokens and spend alongside
missing attribution; classifier overhead is counted separately.

## Routing Evidence

Add `-v routing_details=true` to the pinned read-only SQL export, then use
`investigate --routing-audit`. Add `--routing-by route-agent` to separate agents
within each original route. The default export and reports remain unchanged
apart from the readable public model labels described below.

`--scope-route` and `--scope-agent` select an investigation cohort or the traffic
moved in a what-if scenario. Scenario and workload-map selectors support these
same identities. The [routing guide](../ROUTING.md) has a checked example.

## Readable Models And Pricing Correction

Exact public model IDs in the bundled price catalog now appear in model totals
and routing tables. Private model and deployment names remain aliases. Route and
agent labels remain hidden unless `--show-labels` is explicitly supplied; those
reports contain configuration labels and should be reviewed before sharing.

Labels and what-if pricing use one structured exact match. A recorded
`provider/name` is recognized only when its prefix equals the row's
`custom_llm_provider`, and the catalog contains that exact name with that provider.
This corrects v0.10.1's exclusion of such rows as unknown model prices, including
`openai/gpt-6.1-sol` from the pinned LiteLLM writer. Unknown aliases are not guessed.
Recorded token/spend totals, identity hashes and measured factors do not change.

## Limits

The audit establishes gateway-selected model and deployment, not an independently
verified provider receipt. Several models behind a route show variation, not its
cause. Missing identities stay unknown; failure-row usage has unknown finality.
Routing counters do not reconstruct physical attempts or missing requests.
What-if still needs complete token splits and known prices; its results are
assumption-driven re-pricing, not forecasts, invoices or quality comparisons.

## Install And Verify

Use the [verified installer or manual verification](../OPERATIONS.md#install-and-verify)
with `v0.11.0`. Linux and macOS archives cover AMD64 and ARM64, with checksums,
an SPDX SBOM and signed build provenance. Upgrade the reader before enabling
optional collector summary fields; collector configuration changes remain opt-in.
