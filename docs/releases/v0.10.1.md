# v0.10.1 Release Notes

**See which recorded tokens came from failed requests, and when session agent
attribution is incomplete.** This patch adds reporting context without changing
recorded tokens, spend, session totals or what-if arithmetic.

## Failure Usage

LiteLLM can record token values on interrupted requests without a final provider
receipt. Investigation reports now show the nonzero token subtotal on failure
rows separately in completeness. The values remain included in recorded totals
and are labelled gateway-recorded, finality unknown.

What-if exposes the failure subset that actually passes usage, model, scope and
price-tier checks, with its token and cost contributions. Its existing
billing-finality warning remains. Missing components still exclude a row rather
than being filled with zero. See the [export guide](../../examples/litellm-spend/README.md)
and [what-if guide](../WHAT_IF.md).

## Agent Attribution

The session-budget report now exposes missing agent attribution by call type
and per session. A session with no recorded agent identity displays
`agents: unknown` in text. JSON retains the numeric `agents` field as the
observed distinct count and adds coverage beside it when incomplete.
Two known agents still establish observed sharing even with missing rows;
zero or one known agent does not rule sharing out.

The [session-budget guide](../SESSION_BUDGET.md) describes the pinned LiteLLM
Responses limitation. This is an attribution gap, not evidence of lost requests.

## Compatibility And Limits

Existing goldens are unchanged. New text appears only for applicable failure
usage or incomplete agent attribution; JSON additions do not change existing
field types or values. No agent identity is inferred from a session ID.
These reports describe gateway records, not authenticated final provider usage
or invoices. Reader formats, identity hashing and collector contracts are unchanged.

## Install And Verify

Use the [verified installer or manual verification](../OPERATIONS.md#install-and-verify)
with `v0.10.1`. Linux and macOS archives cover AMD64 and ARM64, with an SPDX SBOM,
checksums and signed build provenance. The [release procedure](../RELEASING.md)
checks packaged commands and pinned SQL exports before and after publication.
