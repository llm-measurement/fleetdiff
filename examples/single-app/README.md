# What Changed In My Agent App?

One application is enough. Compare two one-minute windows, then run the same
investigation over two disjoint producers. No provider account or Docker needed:

```sh
sh examples/investigate.sh
sh examples/investigate.sh --two-stacks
sh examples/investigate.sh --missing-usage
sh examples/investigate.sh --sessions
```

Run from the repository checkout with Go installed. The script builds the current
source. A verified v0.3.0 release binary can read the same sample files directly:

```sh
fleetdiff investigate --before examples/single-app/data/single/before \
  --after examples/single-app/data/single/after --expected app
```

`--expected app` names the `producer_id` in each export. These fixtures focus on
model attempts, token volume, and prompt contributors.

`--sessions` uses a [separate synthetic scenario](../sessions/README.md) with
user and session attribution, including one high-share session flagged for review.

## Expected Answers

| Question | Before | After |
|---|---:|---:|
| Observed model attempts | 2 | 3 |
| Reported input plus output tokens | 200 | 600 |
| Tokens per observed attempt | 100 | 200 |
| Missing usage | 0 | 0 |
| Cache-read tokens, already within input | 10 | 10 |

The 400-token increase splits into +150 from request count and +250 from tokens
per request, using the symmetric arithmetic decomposition in
[the investigation contract](../../docs/INVESTIGATION.md).

Two application-supplied prompt-template keys have observed weights 100 -> 400
and 100 -> 200. The first key's share rises from 50% to about 66.7%. These small
fixtures retain every key, so their frequent-item bounds are exact. The broader
tests exercise nonzero error.

The missing-usage example removes one output-token attribute. It reports 560
recorded tokens and one incomplete request. The report keeps the totals visible
and marks the arithmetic split as `cannot_determine`.

To investigate sessions in your own traffic, collect two compatible windows with
collector v0.3.0's optional
[`topk_keys`](https://github.com/llm-measurement/otelcol-genai-sketches/blob/main/docs/TOPK_KEYS.md).

## Two Stacks, Same Question

`--two-stacks` partitions the same model requests between `gateway` and `direct`.
The script prints `2 expected producer(s) per window (gateway,direct)` before
the report; the default prints `1 expected producer(s) per window (app)`.
Each observation belongs to one producer. Their merged measurements equal the
single application's measurements. This synthetic example represents a LiteLLM
gateway alongside direct instrumentation, with compatible accounting and hashing.

## Fixture Provenance

The files in `data/` were generated by the collector's
`TestLiteLLMInvestigationFixtures` test, with its actual accounting, hashing,
sketches, and summary exporter. Input OTLP is synthetic and source-derived from
LiteLLM revision `96c008f420a21b6561c51494352a68e49043af48`, not captured SDK output.
The [collector recipe](https://github.com/llm-measurement/otelcol-genai-sketches/tree/main/examples/integrations/litellm)
records the tracing mode and optional application annotations.

The test uses a fixed clock, one-minute processing windows starting at Unix
seconds 120 and 180, fixed synthetic producer epochs, and the public test key
`test-secret-32-bytes-for-unit-tests`. Never use that key for real traffic.
Historical span timestamps do not determine these windows.

To regenerate in a collector checkout, choose a new output directory:

```sh
cd connector/genaisketchconnector
GOWORK=off LITELLM_FIXTURE_OUTPUT="$PWD/litellm-fixtures-new" \
  go test -run '^TestLiteLLMInvestigationFixtures$' -count=1
```

Compare that generated directory to `examples/single-app/data` in fleetdiff.
Ordinary tests do not write repository fixtures. Regeneration refuses an existing
output directory. The fleetdiff CLI tests check the expected arithmetic, privacy,
and equivalent one/two-producer answers on the checked-in exports.
