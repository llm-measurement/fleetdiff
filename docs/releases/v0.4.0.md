# v0.4.0 Release Notes

Check whether your own traces can answer usage and session questions before
deploying summary export. `fleetdiff inspect` reads a local OTLP capture and
reports seven readiness questions, missing or unknown-origin usage, label
cardinality, and user/session/prompt rankings.

## Try It

With the verified binary installed:

```sh
fleetdiff inspect traces.jsonl
fleetdiff inspect --format json captures/
fleetdiff inspect --input-format proto - < traces.pb
```

No account, upload, listener, or provider call is involved. The command writes
only to stdout and stderr. A [synthetic demo](https://github.com/llm-measurement/fleetdiff/tree/v0.4.0/examples/inspect)
and three capture recipes cover a Collector file exporter, Python SDK, and
LiteLLM. Preserve your existing trace backend when capturing traffic.

The report starts with how many questions your fields can answer and what to
add next. For an aliased high-cardinality field, rerun with `--show-names` to
see the attribute name locally. Values stay hidden. Custom names can themselves
be sensitive; use the default report when sharing. Hashes remain opt-in.

Exact ranking counts appear as `session-1: 8 (20.00%)`; uncertain results keep
their bounds. Token-count fields are excluded from label review, not accounting.
Unknown usage origin stays unknown: a normalized zero alone cannot identify
whether the provider reported it.

## Verification

The inspector and collector share 36 accounting fixtures, covering model-attempt
scope, missing usage, subsets, provenance, retries, and overflow. Capture recipe
tests exercise actual SDK encoders, a pinned file exporter, and LiteLLM callbacks
against a synthetic local provider. These are integration checks, not a billing
reconciliation or a load test. Packaged binaries are tested on all four supported
targets, with offline non-root checks on Linux.

## Upgrade

Follow the [archive verification instructions](https://github.com/llm-measurement/fleetdiff/blob/main/docs/OPERATIONS.md#install-and-verify)
before replacing the binary. Linux and macOS on AMD64 and ARM64 remain supported.
No collector upgrade, window reset, or summary migration is required. Existing
`compare` and `investigate` behavior and JSON version 1 are unchanged.

Inspection has its own `fleetdiff-inspect/v1` JSON schema and uses the collector's
default accounting contract. Custom mappings and deduplication are outside that
contract. See [inspection formats, limits, and privacy](https://github.com/llm-measurement/fleetdiff/blob/main/docs/INSPECT.md) before using
raw captures. Exit 0 means a completed report, including partial readiness; it
does not mean every question is answerable.
