# fleetdiff v0.15.0

Prepared for release review; publication remains a separate step.

Re-price recorded usage with exact tier-aware arithmetic. What-if text now
leads with Level 1: the same work and output length at the selected dated
prices. Text money uses cent formatting without changing the underlying
accounting or JSON money strings.

## Tier-Aware Repricing

- Version 2 price tables select each request's source and target tiers from
  its complete prompt length, including cache reads and writes. All input,
  cache and output tokens for that request use the selected tier; a move
  fraction does not shrink requests into a cheaper tier.
- Tables include cache-write duration classes. The table selects the assumed
  duration; the reader does not infer a per-request cache-write TTL.
- Text and JSON show target-tier counts for covered source requests before
  the move fraction. These counts are not a forecast of requests sent.
- Summary cohorts are priced only when their minimum and maximum prompt
  lengths select the same source and target tiers. Cohorts spanning tiers
  need request-level rows; their average cannot select a tier.
- Version 1 single-row tables remain readable. Overrides must explicitly
  state replacement tiers or a priced input maximum; they cannot silently
  extend a bundled model's priced range.

The bundled version 2 prices are dated November 19, 2026. Source and target
costs use the same table, not discounted recorded spend. Benchmark verbosity
ratios appear separately as output-length sensitivity, not a traffic forecast,
an invoice or a claim of equivalent quality. See [WHAT_IF](../WHAT_IF.md) for
the commands, price-table formats and coverage rules.

## Money Text And JSON Compatibility

- USD text uses exact ties-to-even cent rounding and a dollar sign. Nonzero
  amounts below one cent remain visible as `<$0.01` or `-<$0.01`.
- Comparisons add decimal places when distinct sub-cent amounts would
  otherwise look identical. This applies to before/after amounts, what-if
  sensitivity values and session spend distributions.
- The money-formatting change does not round stored accounting values or
  change JSON money strings. What-if retains `fleetdiff-what-if/v1` and adds
  optional per-move `target_tiers` details for tier-aware results. Selecting
  different dated prices or tiers can change repricing results independently
  of text formatting.

Text output changes intentionally. Use `--format json` for automation and
retain decimal strings without converting them through binary floating point.

## Opt-In Token Diagnostics

This release also includes the summary-scan diagnostics added since v0.14.1:

- `scan --token-cusum` adds cumulative-sum diagnostics for observed input plus
  output tokens on collector processing-time windows. It does not measure or
  re-price cost. Without the option, existing scan output is unchanged.
- `--cusum-stratum utc-day-of-week` keeps an independent reference and
  statistic for each UTC weekday, without pooling weekdays. It requires
  UTC-aligned daily windows and an explicit integer `--baseline N` counting
  preceding matching weeks (6-384), not a duration or an implicit default.
- Missing or ineligible positions reset the relevant reference and statistic.
  Scores remain uncalibrated diagnostics, not calibrated alerts or false-alarm
  probabilities, and never supply a scan finding. With valid inputs, the
  opt-in command returns exit 4 unless existing scan findings require exit 3;
  an uncalibrated score is not a quiet verdict.
